## What's new in expo/expo expo@58.0.3

This release adds new SwiftUI navigation tools, lets apps request local network access on newer Android devices, and introduces fresh animation presets. It also brings the expo-modules-cli and improves several stability and performance aspects.

### Features

New capabilities for UI and development tooling.

- Apps now request the local network permission on Android 17 and later, enabling network discovery in dev‑launcher builds. ([#50951](https://github.com/expo/expo/pull/50951))
- You can now use smooth, snappy, and bouncy animation presets in UI components. ([#50984](https://github.com/expo/expo/pull/50984))
- Adds SwiftUI navigation and toolbar title display mode modifiers. ([#50687](https://github.com/expo/expo/pull/50687))
- Adds expo-modules-cli with generate-types command. ([#50233](https://github.com/expo/expo/pull/50233))
- Added the expo-modules-cli package and new configuration options for remote notifications. ([#50929](https://github.com/expo/expo/pull/50929))

### Fixes

- The white window no longer appears when a CameraView unmounts during a shutter animation on Android. ([#50950](https://github.com/expo/expo/pull/50950))
- Fixes asset move bug that caused missing media library entries. ([#50817](https://github.com/expo/expo/pull/50817))
- Prevents Pods.xcodeproj UUID collisions during pod install. ([#50946](https://github.com/expo/expo/pull/50946))
- Fixes SQLite statement finalization and failed-close recovery. ([#50121](https://github.com/expo/expo/pull/50121))
- JS inspector middleware now sends the correct Content‑Length header for non‑ASCII responses. ([#49305](https://github.com/expo/expo/pull/49305))
- presentCreateForm now opens the create form and returns a boolean on iOS. ([#50957](https://github.com/expo/expo/pull/50957))
- Expo Router now correctly parses platform-specific routes and loader keys. ([#49035](https://github.com/expo/expo/pull/49035))
- Metro no longer collapses all node_modules stack frames, showing library errors clearly. ([#50973](https://github.com/expo/expo/pull/50973))
- The CLI now keeps node_modules frames when logging server rendering errors. ([#50974](https://github.com/expo/expo/pull/50974))
- The CLI now shows the full call stack for thrown errors even when all frames are collapsed. ([#50975](https://github.com/expo/expo/pull/50975))
- expo-image-manipulator now builds correctly with Swift Package Manager. ([#50961](https://github.com/expo/expo/pull/50961))
- Jest‑expo now correctly merges moduleNameMapper entries for web and node presets. ([#50444](https://github.com/expo/expo/pull/50444))
- Releasing frozen shared objects no longer causes errors on unmount. ([#50970](https://github.com/expo/expo/pull/50970))

### Performance

Under‑the‑hood improvements make JavaScript handling faster and Swift builds more reusable.

- JSI array and dictionary elements are now decoded as unowned values, improving performance. ([#50980](https://github.com/expo/expo/pull/50980))
- JSI decoding now defaults to borrowing, reducing allocations for unowned values. ([#50960](https://github.com/expo/expo/pull/50960))
- Swift compilation cache keys no longer include checkout paths, improving cache reuse. ([#50354](https://github.com/expo/expo/pull/50354))
